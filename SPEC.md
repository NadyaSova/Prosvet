# Просвет — спецификация

Мобильное веб-приложение (PWA), которое с помощью игровой механики помогает регулярно заниматься поиском работы. Документ собран из обсуждения с будущим пользователем (Champion) и служит источником истины для разработки.

## 0. Как читать этот документ

Каждое существенное утверждение помечено:

- **[РЕШЕНО]** — пользователь это сказал или явно выбрал. Не менять без её согласия.
- **[ПРЕДЛОЖЕНО]** — идея из обсуждения, высказанная ассистентом; пользователь не возражала, но и не подтверждала по пунктам. Можно уточнять, упрощать, откладывать. Перед существенным отклонением — спросить.
- **[ОТКРЫТО]** — вопрос не решён. Перед реализацией задать пользователю (или выбрать разумный вариант по умолчанию и явно об этом сказать).

Числа баланса (опыт, цены, вероятности) — все **[ПРЕДЛОЖЕНО]**, стартовые значения для настройки на практике. Их нужно держать в одном конфиг-файле.

## 1. Зачем это нужно

### 1.1. Ситуация [РЕШЕНО]
- Пользователь — разработчик, работает удалённо, параллельно ищет новую работу.
- Поиск работы состоит из разнородной работы:
  1. обновление резюме и подходов к его составлению;
  2. подготовка к собеседованиям, в т. ч. подготовка рассказа о себе и своих навыках;
  3. привычка фиксировать результаты текущей работы: «в процессе я работаю над многими вещами и, может быть, приобретаю важные навыки, но потом про них забываю» → нужна привычка каждый раз, когда делаешь что-то необычное, записывать это (условный «файл навыков»), чтобы потом рассказать на собеседовании;
  4. чтение профильных сообществ — о поиске работы и о возможностях вообще;
  5. чтение вакансий и рассылка резюме.
- Проблема: на всё это сильная демотивация — тема тяжёлая, неприятная и не даёт немедленного результата.

### 1.2. Что уже работало у пользователя [РЕШЕНО]
- **Duolingo.** Закончила курс иврита и курс музыки. Мотивировала **серия** (страх её прервать) и то, что были **короткие задания**, которые можно сделать быстро, — поэтому заходила хотя бы понемногу каждый день.
- **Forest.** Запускаешь таймер, занимаешься задачей, по окончании в лесу вырастает выбранное дерево. Нравилось: смотреть на красивый лес (виды природы успокаивают); то, что у задачи **конечное время** — не «сколько получится» и не «пока не закончишь», а «отработала 30 минут → получила дерево».

### 1.3. Чего пользователь НЕ хочет [РЕШЕНО]
- Не простой чеклист «составь список и радуйся, что вычеркнула пункт».

### 1.4. Чего хочет [РЕШЕНО]
- Приложение, которое запускается на телефоне.
- Мотивирующие фразы.
- Призы за набранное количество очков: **внутренние** (например, «посадить где-то цветочек») и **внешние** (например, «столько-то очков — массаж от мужа»).
- Чтобы было «прикольно».

## 2. Принципы дизайна

1. **Награда за действие, а не за результат.** [ПРЕДЛОЖЕНО] Ответы работодателей от пользователя почти не зависят и приходят с задержкой. Игра считает только то, что пользователь сделал сам.
2. **Отказ — это добыча, а не провал.** [РЕШЕНО] Закрытый отклик — отказ или молчание — приносит награду (см. §9.4 «Голуби и перья»). Иначе первая пачка отказов убьёт мотивацию вместе с приложением. Образ отказа — нейтральный и даже приятный; негативных метафор (шрамы, раны, поражения) не использовать. [РЕШЕНО]
3. **Время, а не объём.** [РЕШЕНО — из опыта с Forest] Задание с таймером засчитывается, когда истекло время, а не когда работа закончена. «Переписывать резюме 30 минут», а не «переписать резюме».
4. **Всегда есть короткое задание.** [РЕШЕНО — из опыта с Duolingo] В любой момент доступно что-то на 5 минут.
5. **Серия есть, но щадящая.** [РЕШЕНО] Окно в 3 дня (см. §8).
6. **Никаких других наказаний.** [ПРЕДЛОЖЕНО] Ничего не вянет, не умирает и не отнимается. Единственное, что можно потерять, — серию.
7. **Игра производит полезное.** [ПРЕДЛОЖЕНО] Журнал достижений (§10) — реальный рабочий материал для резюме и собеседований, его можно выгрузить.
8. **Спокойствие.** [РЕШЕНО — природа успокаивает] Визуально и по тону приложение умиротворяющее, не тревожное и не кричащее.

## 4. Мир [РЕШЕНО в общих чертах, детали ПРЕДЛОЖЕНО]

- Героиня — странница в долине, затянутой серой **хмарью**.
- Каждое выполненное задание отодвигает хмарь и что-то выращивает: дерево, куст, цветы, ручей, позже — постройки (мостик, домик, мельница).
- Цель на длинной дистанции — живая зелёная долина, выращенная своими руками. Это главный «экран-награда», на который приятно смотреть.
- В центре лагеря — **костёр** (визуализация серии, §8).
- Тон текстов: тёплый, немного сказочный, без сюсюканья и без «токсичного позитива». Язык интерфейса — русский. [ПРЕДЛОЖЕНО]

## 5. Основной цикл [ПРЕДЛОЖЕНО]

1. Пользователь открывает приложение → видит долину, костёр и **доску заданий**.
2. На доске 3 задания: разные направления и разные размеры (например, 5 / 15 / 30 минут). Выбор — сознательный и составляет часть игры.
3. Выбранное задание:
   - **таймерное** — запускается таймер; по истечении задание засчитано;
   - **мгновенное** — отмечается сразу (например, «отправила отклик» — улетает голубь, «голубь вернулся», «запись в журнал»).
4. Награда: опыт в ветке направления + золото + **карта добычи** (§9.2) + новый объект в долине с анимацией роста + мотивирующая фраза.
5. Доска пополняется новым заданием.

Дополнительно:
- Кнопка **«Не хочу ничего»** → выдаёт одно крошечное задание (≤5 минут). Главный барьер — начать. [ПРЕДЛОЖЕНО]
- Можно перетянуть доску (заменить 3 задания) — бесплатно 1 раз в день. [ПРЕДЛОЖЕНО]
- Пользователь может запустить таймер на **своё** задание вне доски (произвольный текст + направление + длительность). Реальная жизнь богаче шаблонов. [ПРЕДЛОЖЕНО]

Пять направлений взяты из слов пользователя [РЕШЕНО]; игровые названия и привязка к видам растений — [ПРЕДЛОЖЕНО].

| Ветка | Что покрывает | Растение в долине (предложение) |
|---|---|---|
| **Летопись** | Журнал достижений: фиксация необычного в текущей работе | Дуб |
| **Облик** | Резюме и подход к его составлению, профиль LinkedIn | Берёза |
| **Речь** | Подготовка к собеседованиям, рассказ о себе | Ива |
| **Разведка** | Профильные сообщества, рынок, возможности | Цветы, кусты |

Каждое направление растит в долине свой вид растений → по долине видно, чем пользователь занимался, и это мягко подталкивает к разнообразию.

## 7. Задания

### 7.1. Модель [ПРЕДЛОЖЕНО]
```
TaskTemplate {
  id, branch, title, description?,
  kind: 'timed' | 'instant',
  minutes?: 5 | 10 | 15 | 25 | 30 | 45 | 60,   // для timed
  tags?: string[]
}
```
- Шаблоны хранятся в данных (JSON), пользователь может добавлять/редактировать/скрывать свои.
- Доска собирается так, чтобы 3 задания были из разных веток и разных размеров; ветки, которые давно не трогали, получают повышенный вес.

### 7.2. Стартовый пул [ПРЕДЛОЖЕНО — пример, расширять]

**Летопись**
- 5 мин: Записать одно достижение за эту неделю (мгновенное через форму журнала)
- 10 мин: Дополнить одну черновую запись журнала результатом и цифрами
- 15 мин: Вспомнить и записать одну сложную задачу за последний месяц
- 25 мин: Пройтись по истории задач/коммитов за месяц и выписать 3 кандидата в журнал

**Облик**
- 5 мин: Переписать одну строку резюме
- 15 мин: Сравнить своё резюме с одной вакансией — выписать недостающие ключевые слова
- 30 мин: Работа над резюме (свободная сессия)
- 30 мин: Обновить один раздел профиля LinkedIn
- 15 мин: Перенести одну запись журнала в формулировку для резюме

**Речь**
- 5 мин: Наговорить на диктофон минуту о своём текущем проекте
- 10 мин: Ответить письменно на один типовой вопрос собеседования
- 15 мин: Отрепетировать вслух «расскажите о себе»
- 30 мин: Разобрать одну тему для технического собеседования

**Разведка**
- 5 мин: Прочитать 3 поста в профильном сообществе
- 10 мин: Найти одно новое сообщество / канал / группу по теме
- 15 мин: Изучить одну интересную компанию
- 15 мин: Прочитать одну статью о поиске работы или о рынке

**Охота**
- 5 мин: Сохранить одну интересную вакансию
- 15 мин: Просмотреть свежие вакансии в одном источнике
- 30 мин: Подготовить и отправить один отклик
- мгновенное: «Отправила отклик» (+ компания) → улетает голубь (§9.4)
- мгновенное: ответ по голубю — «Позвали дальше» или «Отказали» (§9.4); слова «отказ» в интерфейсе по возможности избегать, кнопка — «Голубь вернулся»

### 7.3. Таймер [РЕШЕНО — принцип; детали ПРЕДЛОЖЕНО]
- Таймер считает по сохранённой метке времени старта, а не по `setInterval`: должен переживать блокировку экрана, сворачивание и перезагрузку страницы.
- По истечении — экран награды. Если приложение было закрыто, награда выдаётся при следующем открытии.
- **Отмена** — без награды и без штрафа.
- **Пауза** — [РЕШЕНО] одна пауза за задание.
- **«Закончила раньше»** — [РЕШЕНО] частичная награда пропорционально отработанному времени, но без карты добычи.
- Уведомление по окончании таймера — через Notifications API [РЕШЕНО: телефон на Android]. Если уведомления недоступны — вибрация при открытой вкладке. Звука нет (§15, вопрос 6).

## 8. Костёр — серия [РЕШЕНО — правило; визуализация ПРЕДЛОЖЕНО]

**Правило (слова пользователя):** «если после выполнения какого-то задания 2 дня я пропустила, серия не прерывается, а на 3-й она уже прервётся, если ничего не сделаю».

Формально:
- День с хотя бы одним засчитанным заданием — **активный день** (по локальному времени телефона).
- Пусть последний активный день — D. Дни D+1 и D+2 могут быть пустыми. Если день D+3 закончился без действий — серия прерывается.
- Значение серии — число календарных дней с начала текущей серии (с первого активного дня серии). [РЕШЕНО]

Визуализация:
- Костёр в лагере. Яркость отражает, сколько осталось: день действия — полный огонь; D+1 — поменьше; D+2 — слабый; D+3 — угли («сегодня последний день»).
- Поленья сгорают, только если спасают серию; если их не хватает, серия прерывается, а поленья остаются в запасе. [ПРЕДЛОЖЕНО]
- Индикатор на главном экране: число серии + «огонь горит до …».
- **Дрова** [ПРЕДЛОЖЕНО] (аналог заморозки серии в Duolingo): предмет, который изредка выпадает в добыче; если серия должна прерваться, а дрова есть — автоматически сгорает одно полено и окно продлевается на день. Максимум 2 полена в запасе.
- Вехи серии (7, 14, 30, 60, 100 дней серии) дают звезду. [ПРЕДЛОЖЕНО]

## 9. Награды и экономика [ПРЕДЛОЖЕНО целиком; принцип двух видов призов — РЕШЕНО]

### 9.1. Опыт и уровни
- Таймерное задание: 1 опыт за минуту. Мгновенные: отклик (голубь улетел) 10, обычное перо 10, запись в журнал 8, золотое перо (позвали дальше) 30.
- Опыт идёт в ветку задания и в общий уровень персонажа.
- Порог уровня n (и для ветки, и для общего уровня): `50 × n` опыта сверх предыдущего уровня.
- Общий уровень даёт титулы («Путница», «Следопытка», «Хранительница долины»…) и открывает новые районы долины.

### 9.2. Карта добычи
После каждого засчитанного задания тянется одна карта (анимация переворота). Стартовые вероятности:

| Вероятность | Карта |
|---|---|
| 45% | Мотивирующая фраза + 5 золота |
| 25% | +15 золота |
| 14% | Семя редкого растения (декор в долину) |
| 8% | Полено (дрова для костра) |
| 6% | Звезда |
| 2% | Редкость: особый декор (светлячки, радуга над рекой, олень у воды) |

Непредсказуемость награды важнее её размера.

### 9.3. Валюты
- **Золото** — за всё. Тратится на внутренние награды: виды деревьев, украшения лагеря, одежда/облик героини, «посадить цветок в выбранном месте» (пример пользователя — [РЕШЕНО]).
- **Звёзды** — редкие: карты добычи, вехи серии, уровни персонажа, пороги плаща из перьев, золотые перья. Тратятся **только** на внешние призы. Отдельная валюта нужна, чтобы внешние призы нельзя было «нафармить» мелкими заданиями.

### 9.4. Голуби и перья (отклики, отказы и молчание)

Причина [РЕШЕНО]: в ответ на резюме работодатель часто просто молчит, поэтому механика должна закрывать отклик и без явного ответа.

**Голубятня — отдельный экран приложения** [РЕШЕНО]
- На экране сидят 5 голубей, все разные: сочетания 2–3 поз, 2–3 размеров и 4 цветов. Выбрать голубя под настроение — тоже часть игры. [РЕШЕНО]
- Нажимаешь на голубя → приложение спрашивает название компании → голубь улетает. [РЕШЕНО]
- Голубей всегда 5: на место улетевшего прилетает новый, так что отправить отклик можно всегда. [РЕШЕНО]
- Где-то на экране — индикатор голубей в пути. [РЕШЕНО] По каждому: компания, дата отправки, сколько дней в пути. [ПРЕДЛОЖЕНО]
- Плащ из перьев рисуется здесь же: героиня в плаще, счётчик перьев, следующий порог. [РЕШЕНО]
- Вид голубя (поза, размер, цвет) сохраняется в его данных — тот же голубь потом и возвращается. [РЕШЕНО]
- Перо, которое приносит голубь, совпадает с ним по цвету и величине. [РЕШЕНО] Золотое перо — золотое, а величиной — как голубь. [РЕШЕНО] Так плащ складывается из перьев разных цветов и размеров.

**Цикл голубя**
- В день отправки отклика пользователь отмечает его → к компании улетает голубь. [РЕШЕНО]
- Голубь периодически напоминает о себе вопросом в приложении: «Компания X ответила?» [РЕШЕНО]. Когда — на 5-й и 10-й день, карточкой при открытии приложения; по желанию дублировать уведомлением Android [ПРЕДЛОЖЕНО]. Варианты ответа: «Ещё нет» / «Позвали дальше» / «Отказали».
- Ответ можно отметить в любой момент раньше срока — голубь возвращается сразу. [РЕШЕНО]
- **Нет ответа 15 дней** → это считается отказом: голубь возвращается сам и приносит **перо**. [РЕШЕНО]
- «Отказали» (в любой день) → голубь возвращается с **пером**. [РЕШЕНО]
- «Позвали дальше» → голубь приносит **золотое перо**: крупная награда — 30 опыта Охоте и 1 звезда. [РЕШЕНО — идея; числа ПРЕДЛОЖЕНО]
- **Поздний ответ:** если компания позвала дальше уже после того, как голубь вернулся с обычным пером, можно отметить это и получить золотое перо (обычное перо остаётся). [РЕШЕНО]
- Обычное перо также даёт 10 опыта Охоте и фразу из особого пула (`pigeon_return`).

**Плащ из перьев — статус** [РЕШЕНО — принцип «чем больше перьев, тем выше статус»; образ — ПРЕДЛОЖЕНО]
- Перья — не валюта и не удобрение, а **украшение и статус**: каждое перо вшивается в плащ странницы. Чем больше перьев, тем «могущественнее» героиня. [РЕШЕНО]
- Образ — плащ из перьев, своя традиция мира долины. Головной убор вождя коренных народов Америки **не использовать** (это священный предмет в реальных культурах). [РЕШЕНО] Альтернатива плащу — «Венец ветров», свой головной убор долины. [ОТКРЫТО — по умолчанию плащ]
- Пороги: 5, 15, 30, 50, 75, 100 перьев. На каждом пороге плащ заметно меняется (накидка → длинный плащ → переливающийся плащ с хвостом), героиня получает титул и **1 звезду**. [РЕШЕНО — звезда за порог; числа порогов ПРЕДЛОЖЕНО]
- Титулы: «Голубятница» → «Хранительница перьев» → … → «Повелительница ветров». [ПРЕДЛОЖЕНО]
- Золотые перья вшиваются в плащ как особые акценты и тоже считаются в счётчик перьев. [ПРЕДЛОЖЕНО]

**Модель** [ПРЕДЛОЖЕНО]
```
Pigeon {
  id, company, position?, note?,
  look: { pose, size, color }, // вид голубя; перо — того же цвета и размера
  sentAt,                      // дата отправки отклика
  status: 'flying' | 'returned',
  outcome?: 'silence' | 'rejected' | 'invited',
  returnedAt?,
  lateInvite?: boolean,        // позвали после возвращения с обычным пером
  lastAskedAt?                 // когда последний раз спрашивали «ответили?»
}
```
- Автовозврат после 15 дней — чистая функция от текущего времени (как серия), проверяется при открытии приложения.
- Срок 15 дней и дни напоминаний — в конфиге баланса.

### 9.5. Магазин внешних призов [РЕШЕНО — суть; детали ПРЕДЛОЖЕНО]
- Пользователь сама создаёт призы: название, цена в звёздах, необязательная иконка (например, «Массаж от мужа — 3★», «Ужин готовит муж — 2★», «Вечер без домашних дел — 4★»).
- Покупка → **купон**: красивый полноэкранный экран, который можно показать мужу.
- Статусы купона: «куплен» → «выдан» (отмечает пользователь). Муж в приложении ничего не делает. [РЕШЕНО]
- История купонов.

## 10. Летопись — журнал достижений [РЕШЕНО — потребность; форма ПРЕДЛОЖЕНО]

Ключевая полезная часть: превращает текущую работу в материал для резюме и собеседований.

### 10.1. Быстрая запись
- Доступна с главного экрана одной кнопкой.
- Обязательное поле одно: «Что я сделала» (короткий текст). Остальное можно дополнить позже — запись сохраняется как черновик.
- Цель: записать за 30 секунд в момент, когда сделала что-то необычное.

### 10.2. Полная запись (формат STAR-подобный)
```
Achievement {
  id, createdAt, updatedAt,
  title,             // коротко: что сделала
  context?,          // проект / задача / ситуация
  action?,           // что конкретно я сделала, как
  result?,           // результат, по возможности с цифрами
  skills?: string[], // теги навыков
  status: 'draft' | 'complete'
}
```
- Дополнение черновика до полной записи — отдельное задание на доске (ветка Летопись).
- Список записей с фильтром по навыкам.

### 10.3. Выгрузка
- Экспорт в Markdown: один общий файл со всеми записями [РЕШЕНО]; у каждой записи — дата, навыки, статус (формат внутри файла — [ПРЕДЛОЖЕНО], выбрать так, чтобы нормально читалось в Obsidian).
- Пользователь ведёт материалы по поиску работы в Obsidian (папка `Personal/Поиск работы`) — формат должен нормально там читаться.
- Механизм: скачивание файла и/или Web Share API («Поделиться» → в Obsidian / мессенджер / файлы).

## 11. Мотивирующие фразы [РЕШЕНО — фразы нужны; содержание ПРЕДЛОЖЕНО]

- Пул ≥100 фраз в отдельном JSON, по контекстам: `start` (запуск задания), `finish` (завершение), `pigeon_return` (голубь вернулся с пером), `golden_feather` (позвали дальше), `streak` (костёр, вехи), `comeback` (вернулась после перерыва), `idle` (главный экран).
- Тон: тёплый, спокойный, с лёгкой сказочностью мира долины; без восклицательного напора и обещаний «всё будет отлично». Пример: «Хмарь отступила ещё на шаг. Долина помнит каждый.» / «Голубь вернулся. Ещё одно перо в твоём плаще».
- Не повторять одну фразу чаще, чем раз в N показов.

## 12. Долина и графика

### 12.1. Стиль [РЕШЕНО]
- Плоская векторная графика, нарисованная кодом в SVG. Ориентир — `docs/reference-valley.svg` (пользователь видела этот эскиз и он её устраивает).
- Палитра эскиза: тёплое рассветное небо, слоистые зелёные холмы, голубая река, хмарь — серые полупрозрачные пятна, засохшие деревья в хмари — серые штрихи.

### 12.2. Механика долины [ПРЕДЛОЖЕНО]
- Долина — горизонтальная панорама (несколько «экранов» с прокруткой) или сетка участков; хмарь покрывает неоткрытые участки.
- Каждое засчитанное задание ставит объект: вид растения по ветке (§6), размер — по длительности задания (5 мин — куст/цветы, 30 мин — взрослое дерево).
- Анимации: росток → дерево (рост по шагам), хмарь медленно рассеивается, лёгкое покачивание деревьев, огонь костра. Без тяжёлых эффектов — должно плавно работать на телефоне.
- Процедурная генерация с **сидированным RNG**: каждое дерево чуть уникально (высота, оттенок, форма кроны), но стабильно между запусками (сид хранится в данных объекта).
- Смена времени суток по реальному времени — [ПРЕДЛОЖЕНО, фаза 2].
- Когда район полностью открыт — открывается следующий (новые типы ландшафта: озеро, предгорья, луг).

### 12.3. Заменяемость графики [ПРЕДЛОЖЕНО — важно для архитектуры]
- Отделить игровую модель долины (какие объекты, где, какого вида) от рендера.
- Рендер — модуль, который по модели рисует SVG. Чтобы позже можно было подставить готовый набор спрайтов художника (например, бесплатные CC0-наборы Kenney или платные наборы с itch.io), не трогая игровую логику.

## 13. Объём: первая версия и дальше [ПРЕДЛОЖЕНО]

### Фаза 1 — ядро (MVP)
- Главный экран: долина + костёр + доска из 3 заданий + кнопка «Не хочу ничего» + быстрая запись в журнал.
- Таймерные и мгновенные задания, свои задания.
- Опыт по 5 веткам, общий уровень.
- Карта добычи, золото, звёзды.
- Голуби и перья: голубятня, напоминания, автовозврат через 15 дней, плащ из перьев с порогами.
- Костёр/серия с окном 3 дня и дровами.
- Долина: один район, рост объектов, рассеивание хмари.
- Магазин: внутренние награды (несколько видов деревьев/декора) + внешние призы с купонами.
- Летопись: быстрая и полная запись, список, экспорт в Markdown.
- Мотивирующие фразы.
- Резервная копия: экспорт/импорт всех данных в JSON (§14.3).
- Установка на телефон (PWA), офлайн-работа.

### Фаза 2 — глубина (после того как ядро «держит»)
- **Боссы** — большие страшные задачи («переписать резюме целиком») с полосой здоровья в N сессий; каждая сессия наносит урон; победа — редкая награда.
- **Умения веток** — открываются уровнями ветки и меняют правила. Примеры: Летопись — записи журнала дают двойную добычу; Охота — на доске 4 задания вместо 3; Речь — можно перетянуть карту добычи; Разведка — появляются редкие события; Облик — боссы получают больше урона.
- **События** — «странник у костра» предлагает сделку: короткое задание прямо сейчас за двойную награду.
- **Испытания** — цепочки подготовки к конкретному собеседованию.
- **Резонанс** — бонус за то, что за неделю затронуты все ветки.
- Новые районы долины, время суток.

## 14. Техническая часть

### 14.1. Платформа [РЕШЕНО]
- PWA, хостинг GitHub Pages, без бэкенда.
- Данные хранятся только на телефоне.

### 14.2. Стек [ПРЕДЛОЖЕНО — можно выбрать иначе, обосновав]
- Vite + TypeScript.
- UI: Preact (или Svelte / vanilla) — лёгкое, быстрое на телефоне.
- Хранилище: IndexedDB через небольшую обёртку (например, `idb`); схема данных с номером версии и миграциями.
- Service worker для офлайна (например, `vite-plugin-pwa`), манифест с иконкой.
- Деплой: GitHub Actions → GitHub Pages. Учесть `base` path, если сайт живёт в подпапке репозитория.
- Тесты: юнит-тесты на чистую логику (серия, экономика, доска, таймер по меткам времени) — Vitest.

### 14.3. Сохранность данных [ПРЕДЛОЖЕНО — важно]
Раз данные только на телефоне, их легко потерять (очистка браузера, смена телефона):
- Вызвать `navigator.storage.persist()`.
- Экспорт всех данных в JSON-файл и импорт из него (раздел «Настройки»).
- Ненавязчивое напоминание сделать резервную копию раз в 2 недели.
- На iOS: браузер может удалять данные сайтов, которые не установлены на домашний экран и не открывались долго → в онбординге предложить установить приложение.

### 14.4. Логика времени
- Все «дни» считаются по локальному часовому поясу телефона. Пользователь живёт в Израиле (UTC+2/UTC+3, переход на летнее время) — логика серии не должна ломаться на переводе часов.
- Логика серии, таймера и экономики — чистые функции от состояния и текущего времени (время передаётся параметром) → тестируемо.

### 14.5. Конфиг баланса
- Все числа из §8–§9 — в одном файле (`balance.ts` или JSON), чтобы подкручивать без поиска по коду.

### 14.6. Интерфейс
- Mobile-first, портретная ориентация, крупные зоны нажатия.
- Язык интерфейса — русский.
- Светлая тема. Тёмной в фазе 1 нет [РЕШЕНО]; цвета задаются через CSS-переменные, чтобы её можно было добавить позже.
- Звука нет [РЕШЕНО].
